EL ESTÁNDAR DE INTERFAZ DE SOFTWARE PARA MICROCONTROLADORES ARM CORTEX M (CMSIS)

1. ¿Qué es CMSIS?

El Cortex Microcontroller Software Interface Standard (CMSIS) es una capa de abstracción de hardware (HAL) independiente del fabricante para la serie de procesadores Cortex-M. Esto significa que el desarrollador puede escribir código para una amplia variedad de plataformas sin tener que preocuparse demasiado por los detalles del hardware subyacente.

2. Características de programación estandarizadas por CMSIS

CMSIS estandariza varias características de programación, entre ellas:

  • Las funciones para acceder a componentes como el Controlador de Interrupciones Vectorizadas Anidadas (Nested Vectored Interrupt Controller, NVIC), el Bloque de Control del Sistema (System Control Block, SCB) y el Temporizador de Ticks del Sistema (System Tick Timer o SysTick).
  • El acceso a registros especiales, como el registro PRIMASK, y la posibilidad de configurar el registro CONTROL.
  • Funciones para acceder a instrucciones especiales del procesador.
  • Los nombres de las funciones de inicialización del sistema.

3. Beneficios del uso de CMSIS

El uso de CMSIS ofrece numerosos beneficios. Facilita la portabilidad del código de una aplicación entre diferentes microcontroladores basados en Cortex-M. Esto reduce el tiempo necesario para adaptar el software a una nueva placa y permite reutilizar código entre distintos microcontroladores.

CMSIS también mejora la compatibilidad al integrar componentes de software de terceros, como aplicaciones, sistemas operativos embebidos (RTOS), middleware y otros, ya que todos pueden compartir la misma interfaz estándar de CMSIS.

Finalmente, proporciona mayor densidad de código y un menor consumo de memoria, debido a que el código de CMSIS ha sido optimizado y ampliamente probado.

4. Componentes de CMSIS

CMSIS está compuesto por los siguientes elementos:

  • CORE, que ofrece una API estandarizada para el núcleo del procesador Cortex-M y sus periféricos.
  • RTOS (Real-Time Operating System), que proporciona una API común para sistemas operativos en tiempo real junto con una implementación de referencia. Esto permite desarrollar componentes de software compatibles con múltiples RTOS.
  • DSP (Digital Signal Processing), una biblioteca con más de 60 funciones para procesamiento digital de señales, compatible con distintos tipos de datos, tanto de punto fijo como de punto flotante de precisión simple.
  • NN (Neural Network), una colección de funciones (kernels) para redes neuronales desarrolladas para maximizar el rendimiento y minimizar el uso de memoria en procesadores Cortex-M.
  • DAP (Debug Access Port), un firmware para una unidad de depuración que se comunica con el CoreSight Debug Access Port.

5. Herramientas compatibles con CMSIS-DAP

Diversas herramientas pueden utilizar CMSIS-DAP. Algunos ejemplos son:

  • pyOCD, un paquete de Python de código abierto para programar y depurar microcontroladores Arm Cortex-M.
  • Keil MDK.
  • IAR Embedded Workbench.

6. DAPLink y CMSIS-DAP

CMSIS-DAP también puede utilizarse mediante DAPLink, un proyecto de código abierto que implementa el firmware embebido necesario para una sonda (probe) de depuración para procesadores Cortex.

7. Conexión y funcionamiento de la sonda DAPLink

La sonda de depuración DAPLink se conecta al ordenador anfitrión mediante USB. Su interfaz de Human Interface Device (HID) utiliza CMSIS-DAP para acceder al Cortex Debug Access Port de un microcontrolador Arm Cortex a través de USB.

Además, la sonda de depuración DAPLink admite la programación mediante arrastrar y soltar (USB drag-and-drop programming) y proporciona un puerto serie USB.
