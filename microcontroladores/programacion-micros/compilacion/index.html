COMPILACIÓN DE FIRMWARE PARA μC

Diferencias en el desarrollo para microcontroladores y para PC

INTRODUCCIÓN

Cuando comenzamos a programar microcontroladores es común pensar que el proceso de compilaciónes igual al que se utiliza para crear aplicaciones en Windows, Linux o macOS. Después de todo, en ambos casos escribimos código en C o C++, lo compilamos y obtenemos un programa ejecutable. Sin embargo, detrás de esa aparente similitud existe una diferencia fundamental: un microcontrolador no ejecuta el mismo tipo de programas que un computador. Su arquitectura, su memoria y su forma deargar el código hacen que el proceso de compilación sea diferente.

Comprender estas diferencias explica por qué existen compiladores específicos como AVR-GCC o ARM-GCC, qué implica una compilación cruzada y cómo se organiza la memoria dentro del chip.

LA COMPILACIÓN DE UN PROGRAMA. EL COMPILADOR

Compilar consiste en transformar el código fuente de un programa escrito por un ser humano en un lenguaje de programación, como C o C++, en instrucciones máquina que el procesador puede ejecutar directamente. Esa tarea la hae un programa llamado compilador

En una PC el código se compila de forma nativa; el archivo ejecutable se crea y corre en la misma computadora.

En un microcontrolador o un sistema embebido se usa compilación cruzada. Una PC potente (anfitriona) compila el código adaptándolo a la arquitectura específica del microcontrolador de destino (ej. ARM o AVR).

Distinción entre compilar, programar y flashear

Compilar, programar y flashear son dos tareas distintas en el desarrollo embebido. La programación es programar, escribir el código fuente en un lenguaje determinado, de alto o bajo nivel.

La compilación es transformar ese lenguaje entendibe por el ser humao, en un lenguaje que la máquina "entienda". La compilación finaliza cuando las herramientas generan los archivos ELF y HEX en la computadora.

En sistemas embebidos, "quemar", "flashear" o "cargar" son los pasos finales para transferir ese código ya traducido a la memoria del microcontrolador para que pueda ejecutarlo; es una fase posterior donde ese archivo se transmite físicamente a la Flash del microcontrolador para que este pueda ejecutarlo de forma independiente. Quemar es un término antiguo que antes se usaba para los chips que se grababan una sola vez (ROM/PROM), pero hoy se usa como sinónimo de flashear.

Por ejemplo, al escribir un programa en C:

int main(void) {
    return 0;
}

El compilador analiza el código, verifica que sea correcto y genera un archivo ejecutable compuesto por instrucciones específicas para un determinado procesador o código máquina.

El archivo HEX debe grabarse en la memoria Flash mediante un programador. Algunos ejemplos y de acuerdo al microcontrolador de destino, son:

  • USBasp
  • ST-Link
  • J-Link
  • PICkit

Una vez grabado, el programa queda almacenado permanentemente en la memoria Flash hasta que sea reemplazado por otro firmware.

Hay un detalle importante: el código máquina generado depende completamente de la arquitectura del procesador para el que se está compilando.

DIFERENCIAS DE LENGUAJE ENTRE ARQUITECTURAS DE PROCESADORES

Aunque todos los procesadores ejecutan instrucciones binarias, cada familia posee su propio conjunto de instrucciones (Instruction Set Architecture o ISA).

Por ejemplo:

  • Un ATmega328P utiliza la arquitectura AVR de 8 bits.
  • Un STM32F446RE utiliza la arquitectura ARM Cortex-M4 de 32 bits.
  • Un ESP32 emplea la arquitectura Xtensa (o RISC-V en modelos recientes).
  • Un procesador Intel de computadora utiliza x86_64.
  • Una Raspberry Pi 5 utiliza un procesador ARM Cortex-A76 de 64 bits (AArch64).

Debido a estas diferencias físicas en el diseño de los chips, un archivo compilado para una PC o Raspberry Pi no puede ejecutarse en un microcontrolador de 8 o 32 bits, ni el firmware de un AVR funcionará en un STM32.

Cada una de estas arquitecturas posee:

  • Instrucciones diferentes.
  • Registros diferentes.
  • Distintos tamaños de palabra.
  • Diferentes modos de direccionamiento.
  • Distintos mecanismos para acceder a la memoria y a los periféricos.

En consecuencia, un programa compilado para una arquitectura no puede ejecutarse sobre otra distinta.

LA COMPILACIÓN EN ENTORNOS EMBEBIDOS

Cuando ejecutas un programa en una PC, el sistema operativo (Windows, Linux) se encarga de cargarlo en la memoria RAM, darle permisos y gestionarlo.

En un microcontrolador no hay sistema operativo. El código que grabas toma el control total del chip desde el momento en que recibe energía. Ese programa se llama firmware. En lugar de pedirle cosas al sistema operativo, tu código lee y escribe directamente en direcciones fijas del chip para encender un pin, enviar datos por puerto serie o reaccionar cuando alguien presiona un botón.

Un bloque de código simple como:

int suma(int a, int b) {
    return a + b;
}

es legible para el programador, pero el chip necesita secuencias numéricas concretas para operar. Durante la compilación, las herramientas analizan la sintaxis, aplican optimizaciones y generan el código máquina adecuado para el chip de destino.

Etapas del proceso de compilación para un microcontrolador.

El término "compilar" abarca en realidad un flujo de varias herramientas en cadena (toolchain).

El flujo general de construcción de un programa para sistemas embebidos es el siguiente:

  1. Preprocesado: El preprocesador analiza las directivas como #include y #define, expande las macros e incluye los archivos de cabecera.
  2. Compilación: El compilador traduce el código C a lenguaje ensamblador específico de la arquitectura objetivo. Por ejemplo, modificar un puerto con PORTB |= (1 << PB5); genera una instrucción concreta en AVR, pero requerirá una secuencia totalmente distinta en ARM.
  3. Ensamblado: El ensamblador convierte las instrucciones de ensamblador en código máquina binario y genera archivos objeto (.o).
  4. Enlazado (Linking): El enlazador une los archivos objeto, las bibliotecas, el código de arranque (startup code) y la tabla de vectores de interrupción. El resultado es un archivo ejecutable en formato ELF (.elf) que contiene todo el programa junto con metadatos de organización.
  5. Generación de la imagen para Flash: Finalmente, con herramientas como objcopy, se extraen del archivo ELF únicamente los datos que van a grabarse en el chip, generando archivos en formato Intel HEX (.hex) o binario puro (.bin).

El proceso de construcción de un programa es prácticamente el mismo para la mayoría de los microcontroladores, ya sean AVR, ARM Cortex-M (STM32, NXP, Nordic, etc.), PIC, MSP430 o RISC-V. Todas estas arquitecturas siguen las mismas etapas fundamentales: preprocesado, compilación, ensamblado, enlazado y generación de la imagen final que será grabada en la memoria Flash.

Lo que cambia entre una arquitectura y otra es el código que produce el compilador, las bibliotecas utilizadas, el código de inicialización (startup code), el script de enlazado (linker script) y, en algunos casos, el formato del archivo que finalmente se programa en el microcontrolador.

Por ejemplo:

Etapa AVR STM32 (ARM Cortex-M) PIC
Preprocesado Igual Igual Igual
Compilación Genera ensamblador AVR Genera ensamblador Thumb-2 Genera ensamblador PIC
Ensamblado Código máquina AVR Código máquina ARM Código máquina PIC

Aunque el flujo general de compilación es el mismo, la etapa de enlazado presenta diferencias importantes entre las distintas arquitecturas de microcontroladores, principalmente debido a la forma en que cada una organiza su memoria y realiza la inicialización del sistema.

  • AVR: El código de inicio (startup code) es relativamente sencillo y, por lo general, lo proporciona la biblioteca avr-libc. Su función es inicializar las variables globales y estáticas, limpiar la sección .bss y, finalmente, transferir el control a la función main().
  • ARM Cortex-M (STM32): El proceso es más complejo. Intervienen un archivo de inicio, normalmente denominado startup_stm32xxxx.s, un script de enlazado (linker script, .ld) y las bibliotecas del fabricante o CMSIS. Durante el arranque se configura el puntero de pila (stack pointer), se instala la tabla de vectores de interrupción, se copia la sección .data desde la memoria Flash hacia la RAM, se inicializa la sección .bss y, finalmente, se invoca a main().
  • PIC: Microchip proporciona su propio código de inicio, bibliotecas y archivos de configuración adaptados a cada familia de microcontroladores. Aunque los detalles internos difieren de AVR y ARM, el objetivo es el mismo: preparar el entorno de ejecución antes de que comience la ejecución del programa principal.

Función del enlazador y el Linker Script

El enlazador es el encargado de organizar la estructura interna del programa dentro de la memoria física del chip. Mediante un archivo de configuración denominado Linker Script (archivo .ld), el enlazador define exactamente en qué direcciones de memoria se ubican el código, las constantes, las variables globales, la pila (stack) y el área de memoria dinámica (heap).

Diferencia entre archivos ELF y HEX

El archivo ELF es el resultado estructural completo de la compilación. Contiene las secciones de memoria, nombres de funciones, tablas de símbolos y la información de depuración necesaria para herramientas como GDB.

El archivo HEX o BIN es simplemente una extracción simplificada del ELF que contiene únicamente los bytes puros que se van a grabar en la Flash del chip. Por este motivo, para depurar código se utiliza el archivo ELF, mientras que para grabar el chip se usa el HEX o BIN.

El archivo HEX o BIN debe grabarse de forma permanente en la memoria Flash usando un programador físico (como un ST-Link, J-Link o USBasp) o un bootloader. Una vez grabado, el código queda almacenado ahí y el chip empieza a ejecutarlo en cuanto recibe energía.

GESTIÓN DEL PROGRAMA TRAS LA COMPILACIÓN

En una computadora, el sistema operativo recibe el ejecutable y lo acomoda dinámicamente en la memoria RAM para correrlo. En un microcontrolador no existe un sistema operativo encargado de esa tarea.

Distribución de la memoria física

Los microcontroladores dividen sus recursos en diferentes tipos de memoria:

  • Flash: Memoria no volátil donde se guarda el programa y los datos de solo lectura. Por ejemplo, arreglos constantes como const char texto[] = "Hola"; se asignan a la Flash.
  • RAM: Memoria rápida y volátil para variables que cambian durante la ejecución, como char buffer[64];.
  • EEPROM: Presente en algunos chips para guardar datos que deben persistir entre reinicios pero que cambian con poca frecuencia.

Durante el arranque, el código de inicio copia los valores iniciales de las variables globales desde la Flash a la RAM para que el programa pueda modificarlas.

Naturaleza del firmware

El código que corre en un microcontrolador se denomina firmware. A diferencia de una aplicación de escritorio, el firmware toma el control total del hardware: lee sensores, genera señales PWM, controla motores, gestiona pantallas y atiende interrupciones directamente sobre los periféricos del chip.

NECESIDAD DE COMPILADORES ESPECÍFICOS

En una Raspberry Pi o una PC con Linux se puede usar el comando estándar gcc para compilar código que correrá en esa misma máquina. Sin embargo, ese compilador no sabe cómo generar instrucciones para un ATmega328 o un STM32.

Por esa razón se utilizan compiladores cruzados específicos:

  • avr-gcc para chips AVR.
  • arm-none-eabi-gcc para procesadores ARM bare-metal (sin sistema operativo).
  • riscv-none-elf-gcc para microcontroladores RISC-V.
