COMUNICACIÓN SERIAL

INTRODUCCIÓN

La comunicación entre dispositivos digitales consiste, en esencia, en intercambiar información representada mediante bits. Un microcontrolador necesita comunicarse con sensores, memorias, convertidores, otros microcontroladores, módulos de comunicación y numerosos periféricos. Para hacerlo existen diferentes técnicas de transmisión de datos, entre ellas la comunicación paralela y la comunicación serial.

La comunicación serial ocupa un lugar especialmente importante en los sistemas embebidos porque permite intercambiar información utilizando un número reducido de conexiones físicas. Sin embargo, comprenderla correctamente requiere ir más allá de la idea simplificada de que «los bits se envían uno detrás de otro». Hay que entender cómo se almacenan y desplazan los bits, cómo se establece la sincronización temporal y cómo el receptor determina dónde comienza y termina una transmisión.

En este artículo se desarrolla la comunicación serial desde sus fundamentos digitales hasta la distinción entre comunicación síncrona y asíncrona, conceptos que posteriormente permiten comprender interfaces como SPI y UART.

1. COMUNICACIÓN SERIAL Y COMUNICACIÓN PARALELA

Una palabra digital está formada por un conjunto de bits. Por ejemplo, una palabra de ocho bits puede representarse como:

10110010

Cada posición tiene un peso binario diferente. En la representación convencional, el bit situado más a la izquierda es el MSB (Most Significant Bit), mientras que el situado más a la derecha es el LSB (Least Significant Bit):

MSB                         LSB
 ↓                           ↓
1   0   1   1   0   0   1   0

La comunicación paralela y la comunicación serial se diferencian principalmente en la forma en que esos bits son transferidos entre dispositivos.

1.1. Comunicación paralela

En una comunicación paralela, varios o todos los bits de una palabra se transmiten simultáneamente mediante líneas de datos independientes.

Para transmitir una palabra de 8 bits se pueden utilizar ocho líneas:

D7 ─────────────────────────►
D6 ─────────────────────────►
D5 ─────────────────────────►
D4 ─────────────────────────►
D3 ─────────────────────────►
D2 ─────────────────────────►
D1 ─────────────────────────►
D0 ─────────────────────────►

Si se desea transmitir una palabra de 32 bits mediante una interfaz paralela de 32 bits, serían necesarias 32 líneas de datos, además de las líneas que puedan ser necesarias para control, sincronización, alimentación y masa.

Esto puede resultar ventajoso cuando se necesita transferir muchos bits simultáneamente y los dispositivos se encuentran muy próximos. Sin embargo, aumentar el número de líneas también aumenta la complejidad del circuito, del encapsulado, de la placa de circuito impreso y de las conexiones entre dispositivos.

1.2. Comunicación serial

En una comunicación serial, los bits se transfieren secuencialmente, es decir, uno después de otro.

1 → 0 → 1 → 1 → 0 → 0 → 1 → 0

En lugar de necesitar una línea independiente para cada bit, una misma línea de datos puede utilizarse para transferir sucesivamente los bits de la palabra.

La ventaja evidente es la reducción del número de conexiones. Esta característica resulta especialmente útil en sistemas embebidos, donde el número de pines de un microcontrolador es limitado y donde el espacio disponible en la placa puede ser reducido.

Sin embargo, reducir el número de líneas implica resolver otro problema: el receptor necesita saber cuándo debe interpretar la señal eléctrica como un bit. Esta cuestión conduce directamente al concepto de sincronización.

2. EL REGISTRO DE DESPLAZAMIENTO

Para comprender cómo se pueden mover bits de forma secuencial, es necesario conocer el registro de desplazamiento (shift register).

Un registro de desplazamiento es un circuito digital secuencial formado por varios elementos capaces de almacenar un bit, normalmente flip-flops, conectados de manera que el contenido de una posición pueda transferirse a la siguiente mediante una señal de reloj.

Esta definición es importante porque un registro de desplazamiento no es simplemente un conjunto de cables. Es un circuito con capacidad de almacenar bits y trasladarlos entre diferentes posiciones.

2.1. El flip-flop como elemento básico

Un flip-flop puede almacenar un solo bit. Su salida puede encontrarse en uno de dos estados lógicos:

Q = 0

o:

Q = 1

Por tanto, un flip-flop puede considerarse una pequeña celda de almacenamiento de un bit.

Si conectamos ocho flip-flops de forma apropiada, podemos disponer de un circuito capaz de almacenar ocho bits:

┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│ FF  │ │ FF  │ │ FF  │ │ FF  │
│  1  │ │  0  │ │  1  │ │  1  │
└─────┘ └─────┘ └─────┘ └─────┘

┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
│ FF  │ │ FF  │ │ FF  │ │ FF  │
│  0  │ │  0  │ │  1  │ │  0  │
└─────┘ └─────┘ └─────┘ └─────┘

En conjunto tenemos ocho bits almacenados. La organización y las conexiones entre esos flip-flops determinan cómo puede utilizarse el circuito.

2.2. ¿Qué significa desplazar un bit?

Supongamos un registro de cuatro bits que contiene:

1 0 1 1

Si el registro está configurado para desplazar los bits hacia la derecha, cada posición recibe el contenido de la posición situada a su izquierda cuando se produce el evento de reloj correspondiente.

ANTES

1   0   1   1
│   │   │   │
│   └──►│   │
│       └──►│
│           └──►

Después del desplazamiento, suponiendo que entra un nuevo cero por la izquierda:

DESPUÉS

0   1   0   1

El bit que estaba en la primera posición pasó a la segunda; el segundo pasó a la tercera; el tercero pasó a la cuarta, y el último salió del registro.

Eso es exactamente lo que significa desplazar un registro: trasladar los bits almacenados de una posición a otra siguiendo una dirección determinada.

2.3. La señal de reloj controla el desplazamiento

Los bits no se desplazan continuamente. El desplazamiento está controlado por una señal de reloj.

CLK

     ┌───┐     ┌───┐     ┌───┐     ┌───┐
─────┘   └─────┘   └─────┘   └─────┘   └──

     ↑         ↑         ↑         ↑
     │         │         │         │
  desplaz.  desplaz.  desplaz.  desplaz.

Dependiendo del circuito, la transferencia puede producirse en el flanco ascendente o en el flanco descendente del reloj.

Un flanco ascendente es la transición:

0 → 1

y un flanco descendente es:

1 → 0

Esta cuestión será especialmente importante en interfaces síncronas como SPI, donde la relación entre los flancos del reloj y el momento en que se actualizan o muestrean los datos forma parte de la configuración de la interfaz.

3. EL REGISTRO DE DESPLAZAMIENTO COMO CONVERSOR DE DATOS

Una de las características más importantes del registro de desplazamiento es que permite convertir datos entre una representación paralela y una representación serial.

3.1. Conversión paralelo-serie

Supongamos que tenemos almacenado el siguiente dato de ocho bits:

10110010

Todos los bits están disponibles simultáneamente dentro del registro. Si hacemos que el registro desplace los bits y utilizamos una de sus salidas para obtenerlos, podemos producir una secuencia serial:

1 → 0 → 1 → 1 → 0 → 0 → 1 → 0

Esta operación se denomina conversión paralelo-serie o PISO (Parallel-In, Serial-Out).

El registro recibe o carga varios bits simultáneamente y posteriormente los entrega uno a uno.

3.2. Conversión serie-paralelo

El proceso también puede realizarse en sentido contrario.

Supongamos que los bits llegan individualmente:

1 → 0 → 1 → 1 → 0 → 0 → 1 → 0

Cada bit se introduce en el registro mediante la entrada serial. Con cada evento de reloj, los bits almacenados se desplazan y se incorpora el nuevo bit.

Después de recibir los ocho bits, el registro contiene nuevamente la palabra completa:

10110010

Esta operación se denomina conversión serie-paralelo o SIPO (Serial-In, Parallel-Out).

3.3. La importancia de esta función en los sistemas digitales

Esta capacidad explica por qué los registros de desplazamiento son tan importantes en electrónica digital. Permiten conectar un mundo en el que los datos están disponibles simultáneamente con otro en el que los datos deben transferirse secuencialmente.

En términos conceptuales:

          REGISTRO DE DESPLAZAMIENTO
                    │
          ┌─────────┴─────────┐
          │                   │
   Paralelo → Serie     Serie → Paralelo
          │                   │
      Transmisión           Recepción

Los periféricos de comunicación de un microcontrolador son mucho más complejos que un simple registro de desplazamiento, pero este principio continúa siendo fundamental para entender cómo se realiza la transferencia serial de bits.

4. MSB, LSB Y ORDEN DE TRANSMISIÓN

Existe una distinción importante que debe hacerse desde el principio: el significado de un bit dentro de una palabra no es lo mismo que el orden en que ese bit se transmite.

En la representación convencional de un número binario:

10110010
↑      ↑
MSB    LSB

El MSB es el bit de mayor peso y el LSB es el bit de menor peso.

Sin embargo, cuando una palabra se transmite serialmente, existen diferentes posibilidades respecto al orden de transmisión.

4.1. MSB first

Si se transmite primero el bit más significativo, tenemos una transmisión MSB first:

10110010
↑
primero

El orden de transmisión será:

1 → 0 → 1 → 1 → 0 → 0 → 1 → 0

4.2. LSB first

Si se transmite primero el bit menos significativo, tenemos una transmisión LSB first:

10110010
       ↑
     primero

En ese caso, el orden de transmisión será:

0 → 1 → 0 → 0 → 1 → 1 → 0 → 1

Por tanto, no debemos confundir:

  • MSB: bit de mayor peso.
  • LSB: bit de menor peso.
  • MSB first: primero se transmite el MSB.
  • LSB first: primero se transmite el LSB.

La dirección física del desplazamiento dentro del registro y el orden de transmisión están relacionados con la implementación concreta, pero no debemos utilizar indistintamente estos conceptos.

5. EL PROBLEMA DE LA SINCRONIZACIÓN

Cuando los bits se transmiten uno detrás de otro, el receptor necesita conocer el instante apropiado para interpretar cada bit.

Consideremos una secuencia eléctrica como:

10110010

El receptor necesita convertir esa señal física en ocho decisiones independientes:

1 | 0 | 1 | 1 | 0 | 0 | 1 | 0

Para hacerlo correctamente necesita conocer, entre otras cosas:

  • cuándo comienza la transmisión;
  • cuánto dura cada bit;
  • cuándo debe muestrear la señal;
  • cuándo termina una palabra o una trama.

Por este motivo, una comunicación serial no consiste únicamente en conectar una línea entre dos dispositivos. También es necesario establecer un mecanismo que permita al receptor mantener una referencia temporal adecuada.

Existen dos soluciones fundamentales:

  • comunicación serial síncrona;
  • comunicación serial asíncrona.

6. COMUNICACIÓN SERIAL SÍNCRONA

En una comunicación serial síncrona, el transmisor y el receptor comparten una señal de reloj utilizada como referencia temporal para la transferencia de datos.

Conceptualmente:

                TRANSMISOR
                    │
             ┌──────┴──────┐
             │             │
            DATA          CLK
             │             │
             ▼             ▼
        ┌─────────────────────┐
        │       RECEPTOR      │
        └─────────────────────┘

La señal de reloj indica cuándo debe producirse la transferencia o el muestreo de los datos, de acuerdo con las reglas específicas de la interfaz.

6.1. Ventaja de utilizar un reloj compartido

El receptor no necesita adivinar cuándo debe leer cada bit basándose únicamente en su propio reloj. Dispone de una señal externa que proporciona la referencia temporal de la transferencia.

Esto simplifica la sincronización entre los dispositivos, aunque introduce la necesidad de utilizar una línea adicional para transportar el reloj.

6.2. SPI como ejemplo de comunicación síncrona

SPI (Serial Peripheral Interface) es un ejemplo típico de comunicación serial síncrona.

En una conexión SPI convencional encontramos señales como:

SCK  ─────────────► Reloj
MOSI ─────────────► Datos hacia el receptor
MISO ◄───────────── Datos hacia el transmisor
CS   ─────────────► Selección del dispositivo

La señal SCK proporciona el reloj que permite coordinar la transferencia de bits.

Más adelante, al estudiar SPI en detalle, será necesario analizar conceptos como CPOL, CPHA, flanco de muestreo, flanco de cambio, MSB first y LSB first.

7. COMUNICACIÓN SERIAL ASÍNCRONA

En una comunicación serial asíncrona no se transmite una señal de reloj independiente junto con los datos.

El receptor debe utilizar su propio reloj para determinar cuándo debe muestrear la señal recibida.

TRANSMISOR                       RECEPTOR

   TX ─────────────────────────► RX
                                  │
                                  │
                            Reloj local

Para que esto sea posible, transmisor y receptor deben haber establecido previamente determinados parámetros temporales, especialmente la velocidad de transmisión.

7.1. El acuerdo temporal entre transmisor y receptor

Si el transmisor envía los bits a una determinada velocidad y el receptor utiliza una temporización incompatible, el receptor puede muestrear los datos demasiado pronto o demasiado tarde.

El resultado puede ser una interpretación incorrecta de los bits.

Por esta razón, en una comunicación asíncrona ambos extremos deben utilizar una configuración compatible.

7.2. Las tramas permiten identificar el comienzo y el final

Como no existe una línea de reloj compartida, la comunicación asíncrona necesita un mecanismo que permita al receptor identificar el comienzo de una transmisión.

Para ello se utilizan bits de trama (framing bits).

Una representación simplificada de una trama puede ser:

┌───────┬──────────────┬────────┐
│ START │     DATOS    │  STOP  │
└───────┴──────────────┴────────┘

El bit de inicio indica al receptor que está comenzando una nueva trama. A continuación se transmiten los bits de datos y finalmente se utilizan uno o varios bits de parada para indicar el final de la trama.

Dependiendo de la interfaz y de su configuración, una trama puede incluir además otros elementos, como un bit de paridad.

7.3. UART como ejemplo de comunicación asíncrona

UART (Universal Asynchronous Receiver/Transmitter) es uno de los ejemplos más conocidos de comunicación serial asíncrona.

Una conexión UART básica puede representarse como:

TX ─────────────────────────► RX

RX ◄───────────────────────── TX

En este caso no existe una línea de reloj compartida. Los dos dispositivos utilizan sus relojes internos y deben estar configurados de manera compatible.

8. COMPARACIÓN ENTRE COMUNICACIÓN SÍNCRONA Y ASÍNCRONA

Característica Síncrona Asíncrona
Reloj compartido Sí No
Referencia temporal Se proporciona mediante una señal de reloj Se obtiene mediante el reloj local del receptor
Inicio de transmisión Determinado por el protocolo y la señal de control/reloj Se identifica mediante bits de trama
Ejemplo SPI UART

La diferencia fundamental puede resumirse de la siguiente manera:

Comunicación síncrona: el transmisor proporciona una referencia temporal mediante el reloj compartido.

Comunicación asíncrona: el transmisor no proporciona el reloj; transmisor y receptor acuerdan previamente la temporización y utilizan una estructura de trama para sincronizar la recepción.

9. QUÉ DEBEMOS ENTENDER ANTES DE ESTUDIAR SPI Y UART

La comunicación serial no debe entenderse simplemente como «enviar bits uno detrás de otro». Detrás de esa operación aparentemente sencilla existen varios conceptos relacionados.

El primero es el almacenamiento de los bits. Un registro de desplazamiento permite almacenar varios bits y trasladarlos de una posición a otra mediante una señal de reloj.

El segundo es la conversión entre formatos. Un registro puede recibir datos en paralelo y entregarlos serialmente, o recibirlos serialmente y proporcionar posteriormente una palabra paralela.

El tercero es la temporización. El receptor necesita saber cuándo debe interpretar el nivel lógico de la línea como un bit válido.

El cuarto es el orden de transmisión. Una palabra puede transmitirse comenzando por el MSB o por el LSB, dependiendo de las reglas de la interfaz.

Finalmente está la sincronización. En una interfaz síncrona, como SPI, se utiliza una señal de reloj compartida. En una interfaz asíncrona, como UART, cada dispositivo utiliza su propio reloj y la sincronización se consigue mediante la temporización acordada y la estructura de las tramas.

La cadena conceptual que conviene conservar es:

Flip-flop
    ↓
Almacenamiento de un bit
    ↓
Registro de desplazamiento
    ↓
Desplazamiento secuencial de bits
    ↓
Conversión serie ↔ paralelo
    ↓
Transferencia serial
    ↓
Sincronización temporal
    ↓
Comunicación síncrona / asíncrona
    ↓
SPI / UART

Con esta base resulta mucho más sencillo comprender cómo funcionan los periféricos de comunicación integrados en un microcontrolador. Estos periféricos incorporan registros, lógica de control, generadores de reloj, buffers y circuitos de sincronización, pero el principio fundamental de mover y almacenar bits sigue estando presente.

10. Conceptos fundamentales

  • Comunicación paralela: transmite varios bits simultáneamente utilizando líneas independientes.
  • Comunicación serial: transmite los bits secuencialmente.
  • Flip-flop: elemento digital capaz de almacenar un bit.
  • Registro de desplazamiento: conjunto de elementos de almacenamiento conectados para transferir bits entre posiciones mediante una señal de reloj.
  • PISO: conversión de paralelo a serie.
  • SIPO: conversión de serie a paralelo.
  • MSB: bit de mayor peso.
  • LSB: bit de menor peso.
  • MSB first: el MSB se transmite primero.
  • LSB first: el LSB se transmite primero.
  • Comunicación síncrona: utiliza una referencia de reloj compartida entre los dispositivos.
  • Comunicación asíncrona: no utiliza una línea de reloj compartida y requiere una temporización previamente acordada.
  • Trama: estructura que organiza los bits transmitidos y permite al receptor identificar el comienzo y el final de una transmisión.
