MANIPULACIÓN DE BITS EN MICROCONTROLADORES AVR

1. DEMOSTRACIÓN DE MANIPULACIÓN DE BITS

En este enlace hemos aprendido a manipular bits individualmente. Ahora podemos crear un pequeño programa de demostración para experimentar con diferentes patrones de encendido y apagado de LED, secuencias de LED.

La capacidad de establecer, limpiar y conmutar bits individuales proporciona mucha más flexibilidad que la asignación directa (ver este enlace) y constituye una base suficiente para comenzar a experimentar con las operaciones a nivel de bit.

1.1. Código fuente de showingOffBits.c

El siguiente programa utiliza ocho LED conectados al puerto B del microcontrolador AVR. Ejecuta tres animaciones: encendido y apagado progresivo de los LED en ambos sentidos y conmutación aparentemente aleatoria de LED individuales. 

/* Showing off some patterns to practice our bit-twiddling */

// ------- Preamble -------- //
#include <avr/io.h>
#include <util/delay.h>
#include <avr/power.h>

#define DELAYTIME 85 /* milliseconds */
#define LED_PORT PORTB
#define LED_DDR DDRB

int main(void) {

    clock_prescale_set(clock_div_8);

    uint8_t i;
    uint8_t repetitions;
    uint8_t whichLED;
    uint16_t randomNumber = 0x1234;

    // -------- Inits --------- //
    LED_DDR = 0xff; /* all LEDs configured for output */

    // ------ Event loop ------ //
    while (1) {

        /* Go Left */
        for (i = 0; i < 8; i++) {
            LED_PORT |= (1 << i); /* turn on the i'th pin */
            _delay_ms(DELAYTIME); /* wait */
        }

        for (i = 0; i < 8; i++) {
            LED_PORT &= ~(1 << i); /* turn off the i'th pin */
             _delay_ms(DELAYTIME); /* wait */
                }

        _delay_ms(5 * DELAYTIME); /* pause */

        /* Go Right */
        for (i = 7; i < 255; i--) {
            LED_PORT |= (1 << i); /* turn on the i'th pin */
            _delay_ms(DELAYTIME); /* wait */
        }

        for (i = 7; i < 255; i--) {
            LED_PORT &= ~(1 << i); /* turn off the i'th pin */
            _delay_ms(DELAYTIME); /* wait */
        }

        _delay_ms(5 * DELAYTIME); /* pause */

        /* Toggle "random" bits for a while */
        for (repetitions = 0; repetitions < 75; repetitions++) {

            /* "random" number generator */
            randomNumber = 2053 * randomNumber + 13849;

            /* low three bits from high byte */
            whichLED = (randomNumber >> 8) & 0b00000111;

            LED_PORT ^= (1 << whichLED); /* toggle our LED */
             _delay_ms(DELAYTIME);
        }

        LED_PORT = 0; /* all LEDs off */
        _delay_ms(5 * DELAYTIME); /* pause */

    } /* End event loop */

    return (0); /* This line is never real
}

1.2. Inclusión de bibliotecas y definición de constantes

El programa comienza incluyendo tres archivos de cabecera:

  • <avr/io.h>: contiene las definiciones de los registros de entrada y salida, como DDRB y PORTB, correspondientes al microcontrolador AVR seleccionado.
  • <util/delay.h>: proporciona las funciones de retardo, como _delay_ms().
  • <avr/power.h>: proporciona macros para configurar el prescaler del reloj mediante funciones como clock_prescale_set().

A continuación, se definen constantes mediante la directiva #define: 

#define DELAYTIME 85
#define LED_PORT PORTB
#define LED_DDR DDRB

DELAYTIME establece el tiempo de espera en 85 milisegundos. Las constantes LED_PORT y LED_DDR permiten acceder a los registros PORTB y DDRB mediante nombres más descriptivos.

Esta organización facilita la modificación del programa. Por ejemplo, si se desea utilizar otro puerto, pueden cambiarse las definiciones correspondientes sin modificar todas las instrucciones del código.

1.3. Inicialización del programa

Dentro de main(), el programa configura el prescaler del reloj: 

clock_prescale_set(clock_div_8);

Esta instrucción establece un divisor de frecuencia de ocho para el reloj del sistema, siempre que la configuración y el dispositivo AVR sean compatibles con esta función.

Después se declaran las variables utilizadas durante las animaciones: 

uint8_t i;
uint8_t repetitions;
uint8_t whichLED;
uint16_t randomNumber = 0x1234;

Los tipos uint8_t y uint16_t, definidos en las bibliotecas estándar correspondientes, representan enteros sin signo de 8 y 16 bits, respectivamente.

La variable i controla la posición del LED; repetitions cuenta las repeticiones de la tercera animación; whichLED almacena el índice del LED seleccionado, y randomNumber mantiene el estado del generador de números seudoaleatorios.

A continuación, se configura el registro de dirección de datos: 

LED_DDR = 0xff;

El valor hexadecimal 0xFF equivale a 255 en decimal y a la siguiente representación binaria: 

0b11111111

Cada uno de los ocho bits vale uno. Por tanto, todos los pines del puerto B se configuran como salidas, siempre que se trate de un puerto de ocho bits y que dichos pines admitan esa función.

1.4. Estructura del bucle principal

El programa utiliza un bucle infinito: 


    while (1) {
        // Animaciones
    }

Como la condición 1 siempre es verdadera, las instrucciones contenidas en el bucle se ejecutan continuamente. De esta manera, las tres animaciones vuelven a comenzar cada vez que termina la secuencia completa.

El bucle principal se divide en tres partes:

  1. Encender progresivamente los LED y apagarlos en el mismo sentido.
  2. Repetir el proceso en sentido inverso.
  3. Conmutar LED individuales mediante una secuencia seudoaleatoria.

1.5. Primera animación: encendido y apagado progresivo

La rutina denominada Go Left utiliza un bucle for para recorrer los ocho bits del puerto: 


        for (i = 0; i < 8; i++) {
            LED_PORT |= (1 << i);
            _delay_ms(DELAYTIME);
        }

La expresión (1 << i) desplaza un uno binario hacia la posición indicada por i. La operación OR a nivel de bit, representada por |, permite establecer ese bit en el registro LED_PORT sin modificar los demás bits.

Como el programa no apaga los LED durante este primer recorrido, cada iteración deja encendido el LED anterior y activa el siguiente. Al terminar, los ocho LED están encendidos.

El siguiente bucle apaga los LED uno por uno: 


        for (i = 0; i < 8; i++) {
            LED_PORT &= ~(1 << i);
            _delay_ms(DELAYTIME);
        }

En este caso, el desplazamiento genera una máscara que identifica el bit que debe limpiarse. El operador NOT, representado por ~, invierte todos los bits de la máscara, y la operación AND a nivel de bit, representada por &, limpia el bit seleccionado sin alterar los demás.

El resultado es una secuencia en la que los LED se apagan progresivamente, comenzando por el LED de índice cero.

Al finalizar la secuencia, se introduce una pausa: 

_delay_ms(5 * DELAYTIME);

Con un retardo de 85 milisegundos, esta pausa corresponde a 425 milisegundos.

1.6. Segunda animación: recorrido en sentido inverso

La rutina Go Right recorre los LED en orden descendente, comenzando por el bit 7: 


        for (i = 7; i < 255; i--) {
            LED_PORT |= (1 << i);
            _delay_ms(DELAYTIME);
        }

El código “go right” es algo más interesante y presenta una posible trampa al programar microcontroladores. Conceptualmente, resulta sencillo imaginar que comenzamos con: i = 7, y vamos restando uno hasta llegar a cero (0).

El problema está en cómo comprobamos la condición de finalización. Queremos que el bucle for se ejecute cuando i = 0, de manera que pueda apagar LED0.

Si escribimos:


for (i=7; i>0; i--){}

el bucle se detendrá en cuanto i sea cero, por lo que nunca establecerá ni desactivará LED0.

Podríamos intentar solucionarlo comparando con mayor o igual:

for (i=7; i>=0; i--){}

pero entonces obtenemos un sorprendente bucle infinito.

La razón es que i está definida como un entero sin signo (unsigned integer), que cuenta de 0 a 255; solamente está definida para valores positivos.

Cuando restas uno a cero, el valor vuelve a recorrer el rango y pasa al valor máximo, que es 255 en el caso de un entero de 8 bits.

Por lo tanto, la condición:

i >= 0

siempre es verdadera.

Como queremos que el bucle for se ejecute cuando i sea 0 y se detenga posteriormente cuando i sea 255, podemos comprobar:

i < 255

que es exactamente lo que hace el código presentado.

< El siguiente bucle utiliza la misma secuencia descendente, pero limpia los bits en lugar de establecerlos: 


        for (i = 7; i < 255; i--) {
            LED_PORT &= ~(1 << i);
            _delay_ms(DELAYTIME);
        }

De este modo, los LED se apagan en el orden inverso al de la primera animación.

El uso de i < 255 como condición de continuación se explica en la sección 3, ya que depende del comportamiento de los enteros sin signo.

1.7. Tercera animación: conmutación de LED individuales

La tercera parte del programa conmuta LED individuales durante 75 iteraciones: 


        for (repetitions = 0; repetitions < 75; repetitions++) {
            randomNumber = 2053 * randomNumber + 13849;
            whichLED = (randomNumber >> 8) & 0b00000111;
            LED_PORT ^= (1 << whichLED);
            _delay_ms(DELAYTIME);
        }

Finalmente, observemos brevemente la sección de conmutación “aleatoria” del código. El número «aleatorio» en realidad no es verdaderamente aleatorio, pero produce una apariencia suficientemente cercana, por lo que resulta adecuado para este propósito.

Podemos observar cómo se utiliza una máscara de bits para tomar un número aleatorio de 16 bits y convertirlo en un número dentro del intervalo de cero a siete, que corresponde a los números de nuestros LED. Volveremos a utilizar estas técnicas más adelante, pero conviene introducirlas aquí.

Primero convertimos la variable de 16 bits randomNumber en un número de 8 bits desplazándola ocho posiciones: whichLED = (randomNumber >> 8);. Esto conserva los 8 bits más significativos,que son los más aleatorios según este algoritmo rápido y sencillo.

Después necesitamos limitar el número aleatorio al intervalo de cero a siete. ¿Cuál es el número máximo que podemos representar con tres bits? Siete. Por lo tanto, el truco consiste en conservar solamente los tres bits inferiores y poner a cero los cinco superiores. La forma más rápida y sencilla es utilizar AND junto con una máscara: whichLED = whichLED & 0b00000111 . Ahora nuestra variable whichLED estará dentro del intervalo correspondiente al número de LED que realmente tenemos.

Si whichLED contiene un número como cero, tres o siete, todo lo que queda es utilizar XOR y un desplazamiento de bits para conmutar el bit seleccionado aleatoriamente.

En cada iteración se actualiza el número seudoaleatorio, se obtiene un índice entre cero y siete y se conmuta el LED correspondiente mediante XOR.

La operación XOR cambia el estado del bit seleccionado: si estaba en cero, pasa a uno; si estaba en uno, pasa a cero. Los demás bits del puerto permanecen sin cambios.

Una vez completadas las 75 iteraciones, se apagan todos los LED: 

LED_PORT = 0;

La asignación escribe ceros en todos los bits del registro. Después se introduce una pausa antes de que el bucle principal vuelva a comenzar.

1.8. Consideraciones para la ejecución del programa

El ejemplo supone que los ocho LED están conectados al puerto B y que su lógica de encendido corresponde a escribir un uno en el bit de salida. La conexión eléctrica concreta puede modificar ese comportamiento.

También es necesario comprobar que la frecuencia del reloj, la configuración del compilador y las características del microcontrolador sean compatibles con las funciones de retardo utilizadas.

2. BUCLES for

Los bucles for permiten repetir un conjunto de instrucciones mientras se cumpla una condición. Son especialmente útiles en la programación de microcontroladores cuando es necesario recorrer posiciones de bits, registros o elementos de una secuencia.

2.1. Estructura de un bucle for

En C, la estructura general es la siguiente: 

for (inicialización; condición; actualización) {
            // Instrucciones que se repiten
        }

Los tres componentes que aparecen entre paréntesis tienen funciones diferentes.

  1. Inicialización: establece el valor inicial de la variable de control. En el ejemplo, i = 0.
  2. Condición: determina si el bucle debe continuar. En el ejemplo, i < 8.
  3. Actualización: modifica la variable de control al terminar cada iteración. En el ejemplo, i++.

2.2. Ejecución paso a paso

Consideremos el siguiente bucle: 

for (i = 0; i < 8; i++) {
            LED_PORT |= (1 << i);
        }

El funcionamiento es el siguiente:

  1. Se inicializa i con el valor cero.
  2. Se comprueba si i < 8.
  3. Si la condición es verdadera, se ejecuta la instrucción que está dentro de las llaves.
  4. Al terminar la iteración, se ejecuta i++, que incrementa i en uno.
  5. Se vuelve a comprobar la condición y el proceso se repite mientras sea verdadera.
  6. Cuando i alcanza el valor ocho, la condición resulta falsa y el bucle termina.

Por tanto, el cuerpo del bucle se ejecuta ocho veces, con los valores de i comprendidos entre cero y siete.

2.3. Aplicación a la manipulación de bits

En un puerto de ocho bits, los índices válidos van de cero a siete. Por eso, una condición como i < 8 permite recorrer todas las posiciones sin intentar acceder a un noveno bit.

El incremento i++ equivale a sumar uno a la variable. De forma similar, i-- resta uno y permite recorrer las posiciones en sentido descendente.

3. EL PROBLEMA DE LOS ENTEROS SIN SIGNO

La rutina Go Right introduce un caso importante en la programación de microcontroladores: el comportamiento de los enteros sin signo cuando se alcanza el límite inferior de su rango.

3.1. El problema de detener un bucle descendente

Conceptualmente, parece sencillo comenzar con i = 7 y restar uno en cada iteración hasta llegar a cero. Sin embargo, la condición del bucle determina si se procesará también el bit cero.

Si se utiliza la siguiente condición: 

for (i = 7; i > 0; i--) {
            // Operaciones con el bit i
        }

el bucle se ejecuta con los valores de i comprendidos entre siete y uno. Cuando i llega a cero, la condición i > 0 es falsa y el cuerpo no se ejecuta para ese valor. Por tanto, el bit cero queda sin procesar.

3.2. Por qué i >= 0 no funciona

Una solución aparentemente lógica consiste en utilizar una comparación que incluya el cero: 

for (i = 7; i >= 0; i--) {
            // Operaciones con el bit i
        }

Sin embargo, si i es una variable de tipo uint8_t, esta condición provoca que el bucle no termine normalmente.

Un entero sin signo de ocho bits puede representar valores desde cero hasta 255. Cuando se resta uno a una variable cuyo valor es cero, el resultado vuelve al extremo superior del rango: 

0 - 1 = 255

Este comportamiento se debe a la aritmética modular de los enteros sin signo. Después de procesar el valor cero, i pasa a valer 255. La comparación i >= 0 continúa siendo verdadera porque todos los valores representables por un entero sin signo son mayores o iguales que cero.

El resultado es un bucle que continúa recorriendo valores y que, además, podría producir desplazamientos inválidos para el registro de ocho bits.

3.3. Solución utilizada en el ejemplo

El programa original utiliza la condición: 

for (i = 7; i < 255; i--) {
            // Operaciones con el bit i
        }

Esta condición permite ejecutar el cuerpo con los valores de i desde siete hasta cero. Después de procesar el cero, el decremento hace que i pase a 255. En ese momento, la condición i < 255 es falsa y el bucle termina.

La solución funciona con el tipo de variable utilizado en este ejemplo, pero no es necesariamente la forma más clara de escribir un bucle descendente.

3.4. Una alternativa más legible

Para evitar depender de la comparación con 255, puede utilizarse un bucle con una condición de salida explícita: 

uint8_t i = 8;

        while (i > 0) {
            i--;
            // Operaciones con el bit i
        }

En cada iteración se decrementa primero la variable y después se utiliza su valor. De esta manera, el cuerpo se ejecuta con los índices siete, seis, cinco, cuatro, tres, dos, uno y cero. Cuando i llega a cero, la condición del while impide una nueva iteración.

Esta alternativa hace explícita la condición de finalización y evita el desbordamiento de la variable de control.

4. OPERACIONES FUNDAMENTALES DE MANIPULACIÓN DE BITS

Las operaciones fundamentales para manipular bits en C son establecer un bit, limpiarlo y conmutarlo. Estas operaciones se construyen mediante desplazamientos y operadores lógicos a nivel de bit.

4.1. Establecer un bit

Para establecer el bit i de un byte llamado BYTE, se utiliza: 

BYTE |= (1 << i);

El desplazamiento 1 << i genera una máscara cuyo único bit activo se encuentra en la posición i. La operación OR establece ese bit en uno y conserva los valores de los demás bits.

4.2. Limpiar un bit

Para poner a cero el bit i, se utiliza: 

BYTE &= ~(1 << i);

El desplazamiento genera la máscara y el operador NOT invierte sus bits. De esta forma, el bit seleccionado queda a cero en la máscara invertida, mientras que los demás quedan a uno. La operación AND limpia el bit seleccionado y conserva los demás.

4.3. Conmutar un bit

Para invertir el estado del bit i, se utiliza: 

BYTE ^= (1 << i);

La operación XOR conmuta el bit seleccionado. Si estaba a cero, pasa a uno; si estaba a uno, pasa a cero. Los demás bits permanecen sin cambios.

4.4. Modificar varios bits mediante máscaras

Los desplazamientos no tienen que utilizarse necesariamente de forma aislada. Es posible combinar varias máscaras mediante OR para establecer varios bits en una sola operación.

Por ejemplo, para establecer los bits i y j: 

BYTE |= ((1 << i) | (1 << j));

Primero se generan las dos máscaras y después se combinan con OR. La máscara resultante contiene unos en las posiciones que se desean establecer.

El mismo principio puede utilizarse con otras operaciones lógicas cuando se necesita modificar un conjunto de bits.

4.5. Macros para facilitar la lectura del código

Aunque las operaciones directas con desplazamientos y máscaras pueden parecer poco intuitivas al principio, forman parte del uso habitual del lenguaje C en la programación de microcontroladores. Es importante aprender a reconocerlas porque aparecen con frecuencia en bibliotecas, controladores y programas escritos por otros desarrolladores.

Para hacer más legibles estas operaciones, pueden definirse macros: 


#define BV(bit) (1 << bit)
#define setBit(byte, bit) (byte |= BV(bit))
#define clearBit(byte, bit) (byte &= ~BV(bit))
#define toggleBit(byte, bit) (byte ^= BV(bit))

La macro BV(bit) genera una máscara con un uno en la posición indicada. Las otras tres macros utilizan esa máscara para establecer, limpiar o conmutar un bit.

Por ejemplo, para establecer el bit 3 de un registro: 

setBit(PORTB, 3);

Para limpiarlo: 

clearBit(PORTB, 3);

Y para conmutarlo: 

toggleBit(PORTB, 3);

Estas macros facilitan la lectura, pero requieren cuidado: los argumentos deben ser adecuados para las operaciones que realizan y no conviene pasar expresiones que produzcan efectos secundarios al evaluarse.

4.6. Limitaciones y rendimiento

Las macros anteriores están diseñadas para modificar un bit cada vez. En cambio, las operaciones directas con máscaras permiten establecer, limpiar o conmutar varios bits simultáneamente.

En la mayoría de los casos, la diferencia principal es la claridad del código. Cuando es necesario modificar varios bits, resulta más conveniente construir una máscara que represente todas las posiciones requeridas.

En situaciones en las que se ejecutan operaciones de manipulación de bits de forma muy frecuente o con requisitos estrictos de tiempo, el rendimiento debe comprobarse examinando el código generado por el compilador. No debe suponerse que una operación directa siempre será más rápida que una macro, puesto que el compilador puede generar instrucciones equivalentes.

5. CONMUTACIÓN APARENTEMENTE ALEATORIA DE BITS

La tercera animación del programa utiliza una secuencia seudoaleatoria para seleccionar qué LED debe conmutarse en cada iteración.

5.1. Generación de un número seudoaleatorio

La variable randomNumber se inicializa con el valor hexadecimal 0x1234. En cada iteración se actualiza mediante la expresión: 

randomNumber = 2053 * randomNumber + 13849;

Se trata de una forma de generador congruencial lineal, que produce una secuencia determinista de valores a partir de un estado inicial. El resultado depende del valor anterior y de las constantes utilizadas.

Como randomNumber es un entero sin signo de 16 bits, el resultado se almacena dentro del rango representable por ese tipo. La secuencia no es verdaderamente aleatoria: si se repite el mismo estado inicial y se utiliza el mismo algoritmo, se obtiene la misma secuencia.

Para una animación de LED, esta aproximación suele ser suficiente, aunque no debe confundirse con un generador adecuado para aplicaciones criptográficas o para situaciones que exijan aleatoriedad real.

5.2. Obtener los ocho bits superiores

El programa necesita extraer información del byte superior de randomNumber. Para ello, utiliza un desplazamiento hacia la derecha: 

whichLED = (randomNumber >> 8);

Al desplazar ocho posiciones a la derecha un valor de 16 bits, los ocho bits superiores pasan a ocupar las posiciones inferiores del resultado. En una asignación a una variable de ocho bits, se conserva el byte inferior de ese resultado.

En el programa completo, esta operación se combina directamente con una máscara: 

whichLED = (randomNumber >> 8) & 0b00000111;

5.3. Limitar el índice al intervalo de cero a siete

El puerto tiene ocho LED, numerados del cero al siete. Por tanto, el índice seleccionado debe estar dentro de ese intervalo.

Tres bits permiten representar ocho valores distintos: 

000 = 0
        001 = 1
        010 = 2
        011 = 3
        100 = 4
        101 = 5
        110 = 6
        111 = 7

Para conservar únicamente los tres bits inferiores, se utiliza la máscara: 

0b00000111

La operación AND: 

whichLED = whichLED & 0b00000111;

pone a cero los cinco bits superiores y conserva los tres inferiores. De este modo, el resultado queda limitado al intervalo de cero a siete.

En C, esta operación también puede escribirse mediante el operador AND compuesto: 

whichLED &= 0b00000111;

5.4. Conmutar el LED seleccionado

Una vez obtenido el índice, el programa construye una máscara y conmuta el bit correspondiente: 

LED_PORT ^= (1 << whichLED);

Si whichLED contiene cero, se conmuta el bit cero. Si contiene tres, se conmuta el bit tres; y si contiene siete, se conmuta el bit siete.

La combinación de desplazamiento, máscara AND y operación XOR produce una secuencia de encendidos y apagados aparentemente aleatoria. La animación se completa después de 75 iteraciones y, a continuación, el programa apaga todos los LED antes de repetir el ciclo.

5.5. Resumen del procedimiento

  1. Actualizar el estado del generador seudoaleatorio.
  2. Desplazar el número para obtener información de sus ocho bits superiores.
  3. Aplicar una máscara para conservar únicamente tres bits.
  4. Utilizar el resultado como índice del LED que se va a seleccionar.
  5. Conmutar el bit correspondiente mediante XOR.

Esta técnica combina varias operaciones fundamentales de manipulación de bits en una aplicación práctica.

6. RESUMEN DE LA MANIPULACIÓN DE BITS

En este artículo se han estudiado las operaciones básicas de manipulación de bits (bit twiddling) y su aplicación al control de las salidas digitales de un microcontrolador AVR.

6.1. Registros de dirección de datos y registros de salida

En un artículo previose explicó que son los registros de E/S en un mcirocontrolador de la serie ATmega48A/PA/ 88A/PA/ 168A/PA/328/P; en este enlace se explió cómo manipular en C los registros de dirección de datos (DDR) para habilitar determinados pines como salidas. Ahí mismo también se estudió cómo escribir valores lógicos en los registros de salida para controlar el nivel eléctrico de los pines.

El nivel de tensión asociado a un cero(0) o a un uno (1) lógico depende de la alimentación y de las características eléctricas del microcontrolador. Por ejemplo, en un sistema alimentado a 5 V, los niveles de salida suelen corresponder aproximadamente a 0 V y 5 V, respectivamente, dentro de las condiciones especificadas por el fabricante.

6.2. Operadores lógicos a nivel de bit

Para modificar bits individuales o grupos de bits se utilizan los siguientes operadores:

  • OR, representado por |, permite establecer bits.
  • XOR, representado por ^, permite conmutar bits.
  • AND, representado por &, permite conservar o limpiar bits según la máscara utilizada.
  • NOT, representado por ~, invierte los bits de un valor.

También se ha estudiado el desplazamiento de bits, que permite situar un uno en una posición determinada para construir una máscara.

6.3. Las tres operaciones fundamentales

6.3.1. Establecer un bit

BYTE |= (1 << i);

Establece el bit i en uno sin modificar los demás bits.

6.3.2. Limpiar un bit

BYTE &= ~(1 << i);

Establece el bit i en cero y conserva el estado de los demás bits.

6.3.3. Conmutar un bit

BYTE ^= (1 << i);

Invierte el estado del bit i: cambia de cero a uno o de uno a cero.

6.4. Máscaras de bits y aplicación práctica

Una máscara de bits (bitmask) es un valor binario que permite seleccionar las posiciones que deben intervenir en una operación. Combinada con los operadores lógicos, permite modificar bits específicos, tanto individualmente como en grupos.

Estas técnicas son útiles para configurar registros de periféricos, controlar salidas digitales, consultar estados, modificar campos de configuración y trabajar con los recursos internos de los microcontroladores.

Aunque al principio los desplazamientos y las operaciones lógicas pueden parecer difíciles de leer, su dominio es fundamental para comprender programas de sistemas embebidos y trabajar con código escrito por otros desarrolladores.

Los fundamentos estudiados en este capítulo servirán como base para el resto del aprendizaje y para el desarrollo de aplicaciones con microcontroladores AVR.
