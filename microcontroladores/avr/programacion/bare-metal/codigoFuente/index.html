ABSTRACCIÓN DEL HARDWARE

INTRODUCCIÓN

Un ejemplo muy sencillo nos va apermitir comprender el proceso de compilación, programación y ejecución de un programa en un microcontrolador AVR. Vamos a configurar un pin de un dispositivo de la serie ATmega48A/PA/88A/PA/168A/PA/328/P como salida digital y después vamos a colocar ese pin en nivel alto para encender un LED.

1. EL PROGRAMA EN C

El ejemplo parece trivial desde el punto de vista del código C. Sin embargo, si seguimos lo que ocurre dentro del microcontrolador, podemos observar toda la cadena que existe entre una instrucción escrita por el programador y el cambio de tensión que finalmente aparece en una pata física del encapsulado.

El programa completo puede escribirse de la siguiente manera: 

#include <avr/io.h>

int main(void) {
    DDRB |= (1 << PB0);     // Configura PB0 como salida
    PORTB |= (1 << PB0);    // Coloca PB0 en nivel alto

    while (1) {
        // Bucle infinito
    }
}

El programa contiene dos operaciones importantes.

La primera: 

DDRB |= (1 << PB0);

configura PB0 como salida.

La segunda: 

PORTB |= (1 << PB0);

establece el valor lógico de salida de PB0 en uno.

El bucle infinito: 

while (1)
            {
            }

evita que la función main() termine. Una vez configurado el pin y establecido su nivel lógico, no necesitamos ejecutar ninguna otra operación para mantener el LED encendido: el propio hardware del puerto conserva el estado de la salida.

El papel de avr/io.h

La primera línea del programa es: 

#include <avr/io.h>

Este archivo forma parte de avr-libc y proporciona las definiciones necesarias para trabajar con los registros y bits específicos del microcontrolador seleccionado durante la compilación.

Gracias a estas definiciones podemos escribir: 

DDRB
PORTB
PB0

en lugar de tener que escribir directamente las direcciones numéricas de los registros y los números de los bits.

Por tanto, cuando el programador escribe DDRB, no está creando una variable convencional almacenada en la RAM. Está haciendo referencia a un registro de hardware asociado al puerto B del microcontrolador.

Esta distinción es fundamental para entender la programación de AVR. Una expresión como PORTB |= (1 << PB0) parece una operación ordinaria sobre una variable, pero en realidad provoca una operación sobre un circuito electrónico situado dentro del microcontrolador.

2. EL COMPILADOR TRADUCE EL C A INSTRUCCIONES DE LA CPU

El procesador del ATmega168 no ejecuta directamente el código C. El código escrito por el programador debe pasar por el compilador, que lo transforma en instrucciones que la CPU del AVR puede ejecutar.

Por ejemplo, esta expresión: 

DDRB |= (1 << PB0);

implica conceptualmente tres operaciones: 

Leer el valor actual de DDRB
            Modificar el bit correspondiente a PB0
            Escribir el nuevo valor en DDRB

Las instrucciones exactas que produzca el compilador dependen de factores como el microcontrolador seleccionado y las opciones de optimización utilizadas. Por ello, no debemos interpretar esta secuencia como una traducción literal obligatoria a tres instrucciones máquina concretas.

Lo importante para entender el funcionamiento del hardware es que, finalmente, la CPU ejecuta instrucciones que provocan una lectura o escritura sobre el registro de hardware correspondiente.

En este punto desaparece el nivel de abstracción del lenguaje C. La CPU trabaja con instrucciones de la arquitectura AVR y con direcciones, datos y señales internas del microcontrolador.

DDRB determina si PB0 | FUNCIONA COMO ENTRADA O COMO SALIDA

El puerto B dispone de un registro denominado DDRB, cuyo nombre procede de Data Direction Register B.

Cada bit de DDRB está asociado a uno de los bits del puerto B: 

DDRB

            Bit7 Bit6 Bit5 Bit4 Bit3 Bit2 Bit1 Bit0
            ?    ?    ?    ?    ?    ?    ?    1

Para PB0 nos interesa específicamente el bit 0: 

DDRB0 = 1

En los puertos GPIO del dispositivo ATmega, un bit de DDR configurado en 1 establece el pin correspondiente como salida. Si estuviera configurado en 0, el pin funcionaría como entrada.

Por tanto, la instrucción: 

DDRB |= (1 << PB0);

significa, en términos funcionales: 

Conservar los demás bits de DDRB
            y poner a 1 el bit DDRB0.

El operador |= es importante porque permite modificar PB0 sin alterar accidentalmente la configuración de los demás pines del puerto B.

Al quedar: 

DDRB0 = 1

la lógica de control del puerto configura el circuito asociado a PB0 para trabajar como salida.

Sin embargo, en este momento todavía no hemos ordenado al pin que adopte un nivel alto. Hemos definido únicamente su dirección.

PORTB determina el valor de la salida

Una vez configurado PB0 como salida, debemos establecer qué nivel lógico queremos que aparezca en el pin.

Para ello utilizamos el registro PORTB.

La instrucción: 

PORTB |= (1 << PB0);

coloca a uno el bit 0 de PORTB.

Conceptualmente, después de la escritura tenemos: 

PORTB

            Bit7 Bit6 Bit5 Bit4 Bit3 Bit2 Bit1 Bit0
            ?    ?    ?    ?    ?    ?    ?    1

El significado de los demás bits dependerá de cómo estén configurados y utilizados los otros pines del puerto. Para nuestro ejemplo solo nos interesa PORTB0.

Por tanto: 

DDRB0 = 1
            PORTB0 = 1

representa, funcionalmente: 

PB0 configurado como salida
            PB0 conducido a nivel alto

3. PORTB Y EL LATCH DE SALIDA

Para comprender qué sucede a continuación es útil introducir el concepto de latch.

El circuito de salida necesita conservar el valor lógico que se ha escrito aunque la CPU continúe ejecutando otras instrucciones. No sería necesario que la CPU estuviera escribiendo continuamente unos y ceros para mantener el pin en el estado seleccionado.

El hardware dispone para ello de un elemento de almacenamiento asociado a la salida del puerto. De manera simplificada podemos representarlo así: 

CPU
            │
            ▼
            Registro PORTB
            │
            ▼
            Latch de salida
            │
            ▼
            Driver de salida
            │
            ▼
            PB0

Cuando el programa escribe un uno en el bit correspondiente, la lógica de salida conserva ese estado y el driver mantiene el pin en el nivel correspondiente mientras la configuración no cambie.

Aquí conviene hacer una precisión terminológica. Desde el punto de vista del programador, hablamos de PORTB como un registro. Desde el punto de vista del circuito interno, la implementación del puerto contiene elementos de almacenamiento y lógica que permiten conservar y utilizar ese valor.

El diagrama anterior es una representación didáctica del recorrido de la información, no un esquema transistor a transistor del diseño interno del ATmega168.

4. EL DRIVER CMOS CONTROLA EL PIN FISICO

El valor lógico conservado por la lógica de salida controla el circuito electrónico que finalmente conduce el pin.

En un puerto digital CMOS, este circuito utiliza transistores MOS para poder llevar el pin hacia la alimentación o hacia tierra.

De forma muy simplificada podemos representar el comportamiento de una salida CMOS mediante un transistor del lado superior y otro del lado inferior: 

             VCC
                        │
                        [PMOS]
                        │
                        ├────────── PB0
                        │
                        [NMOS]
                        │
                        GND

Esta representación es deliberadamente simplificada. El circuito real de un pin del microcontrolador contiene más elementos y también debe tener en cuenta las estructuras de entrada, protección y otras funciones del pin.

Cuando la lógica de salida solicita un nivel alto, el circuito de salida conduce el pin hacia VCC. Cuando solicita un nivel bajo, lo conduce hacia GND.

En nuestro caso: 

PORTB0 = 1
                    ↓
            Driver de salida
                    ↓
            PB0 ≈ VCC

Si el microcontrolador está alimentado a 5 V, el pin tenderá a presentar un nivel cercano a VCC cuando está en estado alto. Esto no significa que el pin sea una fuente ideal de 5 V: la tensión real depende de la corriente que esté entregando y de las características eléctricas especificadas por el fabricante.

5. EL NIVEL LÓGICO SE CONVIERTE EN UNA TENSIÓN ELÉCTRICA

Hasta este momento hemos hablado principalmente en términos de bits y niveles lógicos. Ahora llegamos al punto en el que esa información se convierte en una magnitud eléctrica observable con un instrumento de medida.

Si PB0 está configurado como salida y su valor lógico es uno, el driver de salida lleva el pin hacia VCC. 

PORTB0 = 1
                │
                ▼
            Driver de salida
                │
                ▼
            PB0 → nivel alto

Si medimos entre PB0 y GND con un multímetro, podremos observar una tensión próxima a la tensión de alimentación del microcontrolador, siempre dentro de las condiciones de carga especificadas para el pin.

La Corriente Circula por el Led

Ahora podemos completar el recorrido conectando el pin con el circuito externo. 

PB0
            │
            ▼
            [220 Ω]
            │
            ▼
            LED
            │
            ▼
            GND

Cuando PB0 se encuentra en nivel alto, existe una diferencia de potencial entre el pin y tierra.

Esa diferencia de potencial produce una corriente que circula aproximadamente por el siguiente camino: 

VCC del microcontrolador
                    │
                    ▼
            Circuito de salida de PB0
                    │
                    ▼
            Pin PB0
                    │
                    ▼
            Resistencia
                    │
                    ▼
            LED
                    │
                    ▼
            GND

La resistencia limita la corriente y el LED convierte parte de la energía eléctrica en radiación luminosa.

El LED se enciende, pero el proceso que acabamos de describir comenzó mucho antes de que apareciera corriente en el circuito externo. Comenzó con una instrucción escrita en C.

6. EL RECORRIDO COMPLETO DESDE EL CÓDIGO HASTA EL PIN

Podemos reunir ahora todos los niveles que hemos estudiado.

6.1. Desde el código fuente hasta la CPU

DDRB |= (1 << PB0);
            PORTB |= (1 << PB0);

El código C es procesado por el compilador y transformado en instrucciones de la arquitectura AVR. Esas instrucciones son almacenadas en el programa del microcontrolador y posteriormente ejecutadas por la CPU.

6.2. Desde la CPU hasta DDRB

La CPU ejecuta las instrucciones correspondientes y accede al registro DDRB. Al quedar DDRB0 = 1, la lógica del puerto configura PB0 como salida.

6.3. Desde la CPU hasta PORTB

Posteriormente la CPU escribe un uno en PORTB0. Ese valor pasa a la lógica de almacenamiento y control de la salida.

6.4. Desde PORTB hasta el driver

El valor de salida es conservado por la lógica correspondiente y utilizado por el circuito de salida del puerto. El driver CMOS recibe la orden de establecer un nivel alto.

6.5. Desde el driver hasta el pin físico

El driver conduce PB0 hacia VCC. El resultado puede medirse directamente en la pata física del encapsulado.

6.6. Desde el pin hasta el LED

Finalmente, la tensión presente en PB0 provoca una corriente a través de la resistencia y del LED conectado a tierra. El LED emite luz.

Este recorrido permite relacionar conceptos que a menudo se estudian por separado. El registro DDRB ya no aparece como una simple posición de memoria; podemos verlo como parte de la lógica que determina el funcionamiento del pin. Del mismo modo, PORTB deja de ser simplemente un nombre utilizado en un programa y pasa a entenderse como la interfaz de control mediante la cual el software determina el estado de la salida.
