EJEMPLO COMPLETO: ENCENDER UN LED EN UN ATMEGA168

RESUMEN

Este artículo muestra un ejemplo completo de programación de un microcontrolador AVR directamente mediante sus registros. El ejemplo consiste en encender un LED conectado a un pin del ATmega168. A partir de un programa escrito en C, se analiza el recorrido que sigue la información desde el código fuente hasta la corriente que circula por el LED.

INTRODUCCIÓN

Hasta este punto hemos visto que un microcontrolador no debe entenderse simplemente como un dispositivo al que se le escriben instrucciones para que "haga cosas". Detrás de cada instrucción que modifica un puerto de entrada/salida existe una relación directa entre el programa, los registros de hardware y los circuitos electrónicos que finalmente controlan los pines del microcontrolador.

Un ejemplo muy sencillo permite reunir todos esos conceptos. Vamos a configurar un pin del ATmega168 como salida digital y después vamos a colocar ese pin en nivel alto para encender un LED.

El ejemplo parece trivial desde el punto de vista del código C. Sin embargo, si seguimos lo que ocurre dentro del microcontrolador, podemos observar toda la cadena que existe entre una instrucción escrita por el programador y el cambio de tensión que finalmente aparece en una pata física del encapsulado.

El recorrido que estudiaremos es:

1. EL CIRCUITO DEL EJEMPLO

Para este ejemplo utilizaremos el pin PB0 del puerto B del ATmega168. En un ATmega168 con encapsulado DIP de 28 pines, PB0 corresponde al pin físico 14.

Antes de conectar el LED, debemos montar en la protoboard el circuito mínimo necesario para que el ATmega168 funcione de forma independiente (standalone). En este montaje utilizaremos el oscilador interno del microcontrolador, por lo que no es necesario añadir un cristal externo ni sus condensadores.

1. Alimentación del ATmega168

El primer paso consiste en conectar correctamente la alimentación del microcontrolador:

  • VCC (pin 7) → positivo de la alimentación.
  • AVCC (pin 20) → positivo de la alimentación.
  • GND (pin 8) → tierra.
  • GND (pin 22) → tierra.

AVCC debe conectarse a VCC incluso si el programa no utiliza el convertidor analógico-digital (ADC), ya que este pin también está relacionado con la alimentación del puerto C.

2. Condensador de desacoplo

Se recomienda colocar un condensador cerámico de 100 nF entre VCC y GND, situado lo más cerca posible del ATmega168. Su función es reducir las pequeñas perturbaciones de la tensión de alimentación producidas por los cambios de corriente internos del microcontrolador.

3. Conexión del RESET

El pin RESET (pin 1) debe mantenerse normalmente en nivel alto para que el microcontrolador pueda ejecutar el programa. Para ello, se conecta una resistencia de aproximadamente 10 kΩ entre RESET y VCC.

La resistencia actúa como pull-up y evita que el pin RESET quede flotante, reduciendo la posibilidad de reinicios provocados por perturbaciones eléctricas.

4. Conexión del LED en PB0

Una vez establecidas las conexiones básicas del microcontrolador, podemos conectar el LED que utilizaremos para comprobar el funcionamiento del programa.

El LED no debe conectarse directamente al pin PB0 sin una resistencia. La resistencia limita la corriente que circula por el LED y protege tanto al LED como al circuito de salida del microcontrolador.

Una conexión sencilla es:

PB0 (pin 14) → resistencia de 220 Ω → LED → GND

Cuando PB0 se encuentra en nivel alto, existe una diferencia de potencial entre el pin y GND. Esta diferencia de potencial hace que circule corriente a través de la resistencia y del LED, provocando que el LED emita luz.

La resistencia de 220 Ω es solamente un valor de ejemplo. El valor adecuado depende de la tensión de alimentación, de la caída de tensión del LED y de la corriente que se quiera hacer circular. En todos los casos deben respetarse las especificaciones eléctricas del ATmega168, especialmente los límites de corriente de sus pines.

5. Circuito standalone completo

Al integrar las conexiones anteriores obtenemos el circuito mínimo del ATmega168 para este ejemplo: alimentación, desacoplo, resistencia de pull-up en RESET y LED conectado a PB0. El microcontrolador puede funcionar de forma independiente en la protoboard utilizando su oscilador interno.

2. EL PROGRAMA EN C

El programa completo puede escribirse de la siguiente manera: 

#include <avr/io.h>

            int main(void)
            {
                DDRB |= (1 << PB0);     // Configura PB0 como salida
                PORTB |= (1 << PB0);    // Coloca PB0 en nivel alto

                while (1)
                {
                }
            }

El programa contiene dos operaciones importantes.

La primera: 

DDRB |= (1 << PB0);

configura PB0 como salida.

La segunda: 

PORTB |= (1 << PB0);

establece el valor lógico de salida de PB0 en uno.

El bucle infinito: 

while (1)
            {
            }

evita que la función main() termine. Una vez configurado el pin y establecido su nivel lógico, no necesitamos ejecutar ninguna otra operación para mantener el LED encendido: el propio hardware del puerto conserva el estado de la salida.

3. EL PAPEL DE AVR/IO.H

La primera línea del programa es: 

#include <avr/io.h>

Este archivo forma parte de avr-libc y proporciona las definiciones necesarias para trabajar con los registros y bits específicos del microcontrolador seleccionado durante la compilación.

Gracias a estas definiciones podemos escribir: 

DDRB
            PORTB
            PB0

en lugar de tener que escribir directamente las direcciones numéricas de los registros y los números de los bits.

Por tanto, cuando el programador escribe DDRB, no está creando una variable convencional almacenada en la RAM. Está haciendo referencia a un registro de hardware asociado al puerto B del microcontrolador.

Esta distinción es fundamental para entender la programación de AVR. Una expresión como PORTB |= (1 << PB0) parece una operación ordinaria sobre una variable, pero en realidad provoca una operación sobre un circuito electrónico situado dentro del microcontrolador.

4. EL COMPILADOR TRADUCE EL C A INSTRUCCIONES DE LA CPU

El procesador del ATmega168 no ejecuta directamente el código C. El código escrito por el programador debe pasar por el compilador, que lo transforma en instrucciones que la CPU del AVR puede ejecutar.

Por ejemplo, esta expresión: 

DDRB |= (1 << PB0);

implica conceptualmente tres operaciones: 

Leer el valor actual de DDRB
            Modificar el bit correspondiente a PB0
            Escribir el nuevo valor en DDRB

Las instrucciones exactas que produzca el compilador dependen de factores como el microcontrolador seleccionado y las opciones de optimización utilizadas. Por ello, no debemos interpretar esta secuencia como una traducción literal obligatoria a tres instrucciones máquina concretas.

Lo importante para entender el funcionamiento del hardware es que, finalmente, la CPU ejecuta instrucciones que provocan una lectura o escritura sobre el registro de hardware correspondiente.

En este punto desaparece el nivel de abstracción del lenguaje C. La CPU trabaja con instrucciones de la arquitectura AVR y con direcciones, datos y señales internas del microcontrolador.

5. DDRB DETERMINA SI PB0 FUNCIONA COMO ENTRADA O COMO SALIDA

El puerto B dispone de un registro denominado DDRB, cuyo nombre procede de Data Direction Register B.

Cada bit de DDRB está asociado a uno de los bits del puerto B: 

DDRB

            Bit7 Bit6 Bit5 Bit4 Bit3 Bit2 Bit1 Bit0
            ?    ?    ?    ?    ?    ?    ?    1

Para PB0 nos interesa específicamente el bit 0: 

DDRB0 = 1

En los puertos GPIO del ATmega168, un bit de DDR configurado en 1 establece el pin correspondiente como salida. Si estuviera configurado en 0, el pin funcionaría como entrada.

Por eso: 

DDRB |= (1 << PB0);

significa, en términos funcionales: 

Conservar los demás bits de DDRB
            y poner a 1 el bit DDRB0.

El operador |= es importante porque permite modificar PB0 sin alterar accidentalmente la configuración de los demás pines del puerto B.

6. LA ESCRITURA EN DDRB LLEGA AL CIRCUITO DEL PUERTO

Cuando la CPU escribe un nuevo valor en DDRB, ese valor no queda simplemente almacenado para ser utilizado posteriormente por el software. El contenido del registro está conectado funcionalmente con la lógica interna del puerto.

Al quedar: 

DDRB0 = 1

la lógica de control del puerto configura el circuito asociado a PB0 para trabajar como salida.

Es importante expresar correctamente qué significa esto. No se trata simplemente de que un interruptor interno "desconecte una entrada y conecte una salida". El circuito de cada pin dispone de lógica de entrada, lógica de salida y circuitos de control que determinan cómo se conecta funcionalmente el pin con esas estructuras internas.

Para nuestro ejemplo, el resultado práctico es que el circuito de salida de PB0 queda habilitado.

Sin embargo, en este momento todavía no hemos ordenado al pin que adopte un nivel alto. Hemos definido únicamente su dirección.

7. PORTB DETERMINA EL VALOR DE LA SALIDA

Una vez configurado PB0 como salida, debemos establecer qué nivel lógico queremos que aparezca en el pin.

Para ello utilizamos el registro PORTB.

La instrucción: 

PORTB |= (1 << PB0);

coloca a uno el bit 0 de PORTB.

Conceptualmente, después de la escritura tenemos: 

PORTB

            Bit7 Bit6 Bit5 Bit4 Bit3 Bit2 Bit1 Bit0
            ?    ?    ?    ?    ?    ?    ?    1

El significado de los demás bits dependerá de cómo estén configurados y utilizados los otros pines del puerto. Para nuestro ejemplo solo nos interesa PORTB0.

Cuando PB0 está configurado como salida, el valor almacenado en el bit correspondiente de PORTB determina el nivel que el circuito de salida intenta establecer en el pin.

Por tanto: 

DDRB0 = 1
            PORTB0 = 1

representa, funcionalmente: 

PB0 configurado como salida
            PB0 conducido a nivel alto

8. PORTB Y EL LATCH DE SALIDA

Para comprender qué sucede a continuación es útil introducir el concepto de latch.

El circuito de salida necesita conservar el valor lógico que se ha escrito aunque la CPU continúe ejecutando otras instrucciones. No sería necesario que la CPU estuviera escribiendo continuamente unos y ceros para mantener el pin en el estado seleccionado.

El hardware dispone para ello de un elemento de almacenamiento asociado a la salida del puerto. De manera simplificada podemos representarlo así: 

CPU
            │
            ▼
            Registro PORTB
            │
            ▼
            Latch de salida
            │
            ▼
            Driver de salida
            │
            ▼
            PB0

Cuando el programa escribe un uno en el bit correspondiente, la lógica de salida conserva ese estado y el driver mantiene el pin en el nivel correspondiente mientras la configuración no cambie.

Aquí conviene hacer una precisión terminológica. Desde el punto de vista del programador, hablamos de PORTB como un registro. Desde el punto de vista del circuito interno, la implementación del puerto contiene elementos de almacenamiento y lógica que permiten conservar y utilizar ese valor. No debemos imaginar necesariamente que existe una sucesión de bloques independientes llamados "registro PORTB", "latch" y "driver" exactamente como aparecerían en un diagrama conceptual.

El diagrama anterior es una representación didáctica del recorrido de la información, no un esquema transistor a transistor del diseño interno del ATmega168.

9. EL DRIVER CMOS CONTROLA EL PIN FÍSICO

El valor lógico conservado por la lógica de salida controla el circuito electrónico que finalmente conduce el pin.

En un puerto digital CMOS, este circuito utiliza transistores MOS para poder llevar el pin hacia la alimentación o hacia tierra.

De forma muy simplificada podemos representar el comportamiento de una salida CMOS mediante un transistor del lado superior y otro del lado inferior: 

             VCC
                        │
                        [PMOS]
                        │
                        ├────────── PB0
                        │
                        [NMOS]
                        │
                        GND

Esta representación es deliberadamente simplificada. El circuito real de un pin del microcontrolador contiene más elementos y también debe tener en cuenta las estructuras de entrada, protección y otras funciones del pin.

Cuando la lógica de salida solicita un nivel alto, el circuito de salida conduce el pin hacia VCC. Cuando solicita un nivel bajo, lo conduce hacia GND.

En nuestro caso: 

PORTB0 = 1
                    ↓
            Driver de salida
                    ↓
            PB0 ≈ VCC

Si el microcontrolador está alimentado a 5 V, el pin tenderá a presentar un nivel cercano a VCC cuando está en estado alto. Esto no significa que el pin sea una fuente ideal de 5 V: la tensión real depende de la corriente que esté entregando y de las características eléctricas especificadas por el fabricante.

10. EL NIVEL LÓGICO SE CONVIERTE EN UNA TENSIÓN ELÉCTRICA

Hasta este momento hemos hablado principalmente en términos de bits y niveles lógicos. Ahora llegamos al punto en el que esa información se convierte en una magnitud eléctrica observable con un instrumento de medida.

Si PB0 está configurado como salida y su valor lógico es uno, el driver de salida lleva el pin hacia VCC. 

PORTB0 = 1
                │
                ▼
            Driver de salida
                │
                ▼
            PB0 → nivel alto

Si medimos entre PB0 y GND con un multímetro, podremos observar una tensión próxima a la tensión de alimentación del microcontrolador, siempre dentro de las condiciones de carga especificadas para el pin.

Por tanto, el "1 lógico" que aparece en el programa no es una abstracción que desaparece dentro del microcontrolador. Termina produciendo un estado eléctrico concreto en el pin físico.

11. LA CORRIENTE CIRCULA POR EL LED

Ahora podemos completar el recorrido conectando el pin con el circuito externo. 

PB0
            │
            ▼
            [220 Ω]
            │
            ▼
            LED
            │
            ▼
            GND

Cuando PB0 se encuentra en nivel alto, existe una diferencia de potencial entre el pin y tierra.

Esa diferencia de potencial produce una corriente que circula aproximadamente por el siguiente camino: 

VCC del microcontrolador
                    │
                    ▼
            Circuito de salida de PB0
                    │
                    ▼
            Pin PB0
                    │
                    ▼
            Resistencia
                    │
                    ▼
            LED
                    │
                    ▼
            GND

La resistencia limita la corriente y el LED convierte parte de la energía eléctrica en radiación luminosa.

El LED se enciende, pero el proceso que acabamos de describir comenzó mucho antes de que apareciera corriente en el circuito externo. Comenzó con una instrucción escrita en C.

12. EL RECORRIDO COMPLETO DESDE EL CÓDIGO HASTA EL PIN

Podemos reunir ahora todos los niveles que hemos estudiado.

12.1. Desde el código fuente hasta la CPU

DDRB |= (1 << PB0);
            PORTB |= (1 << PB0);

El código C es procesado por el compilador y transformado en instrucciones de la arquitectura AVR. Esas instrucciones son almacenadas en el programa del microcontrolador y posteriormente ejecutadas por la CPU.

12.2. Desde la CPU hasta DDRB

La CPU ejecuta las instrucciones correspondientes y accede al registro DDRB. Al quedar DDRB0 = 1, la lógica del puerto configura PB0 como salida.

12.3. Desde la CPU hasta PORTB

Posteriormente la CPU escribe un uno en PORTB0. Ese valor pasa a la lógica de almacenamiento y control de la salida.

12.4. Desde PORTB hasta el driver

El valor de salida es conservado por la lógica correspondiente y utilizado por el circuito de salida del puerto. El driver CMOS recibe la orden de establecer un nivel alto.

12.5. Desde el driver hasta el pin físico

El driver conduce PB0 hacia VCC. El resultado puede medirse directamente en la pata física del encapsulado.

12.6. Desde el pin hasta el LED

Finalmente, la tensión presente en PB0 provoca una corriente a través de la resistencia y del LED conectado a tierra. El LED emite luz.

13. RESUMEN DEL FUNCIONAMIENTO

Todo el proceso puede resumirse en la siguiente secuencia: 

Programa en C

            DDRB |= (1 << PB0);
            PORTB |= (1 << PB0);

                    │
                    ▼

            Compilador

                    │
                    ▼

            Instrucciones máquina

                    │
                    ▼

            CPU

                    │
                    ▼

            DDRB0 = 1
            PB0 configurado como salida

                    │
                    ▼

            PORTB0 = 1
            Nivel lógico de salida = 1

                    │
                    ▼

            Lógica de almacenamiento
            y control de salida

                    │
                    ▼

            Driver CMOS

                    │
                    ▼

            Pin físico PB0
            ≈ VCC

                    │
                    ▼

            Resistencia + LED

                    │
                    ▼

                    │

            LED encendido

Este recorrido permite relacionar conceptos que a menudo se estudian por separado. El registro DDRB ya no aparece como una simple posición de memoria; podemos verlo como parte de la lógica que determina el funcionamiento del pin. Del mismo modo, PORTB deja de ser simplemente un nombre utilizado en un programa y pasa a entenderse como la interfaz de control mediante la cual el software determina el estado de la salida.

14. REFLEXIÓN FINAL

Este sencillo ejemplo muestra por qué la programación de un microcontrolador no consiste únicamente en escribir instrucciones en C. Entre el código fuente y el componente conectado al pin existe una cadena completa de hardware y software que debe funcionar de forma coordinada.

Cuando el programador escribe: 

DDRB |= (1 << PB0);
            PORTB |= (1 << PB0);

no está enviando directamente una orden al LED. Primero está configurando un registro de hardware y después está escribiendo un valor en otro registro. La CPU ejecuta las instrucciones generadas por el compilador, la lógica del puerto interpreta esos valores y finalmente el circuito de salida establece una tensión eléctrica en PB0.

Solo después de todo ese recorrido aparece el efecto observable fuera del microcontrolador: la corriente circula por el circuito externo y el LED se enciende.

Esta relación entre software y hardware es uno de los conceptos fundamentales de los sistemas embebidos. Un registro de E/S no es simplemente una variable especial del lenguaje C. Es la interfaz mediante la cual el software puede controlar circuitos electrónicos reales dentro del microcontrolador.

Comprender este recorrido resulta especialmente importante cuando se programa un AVR directamente mediante sus registros, sin utilizar una capa de abstracción como la que proporcionan determinados entornos de desarrollo. En ese contexto, expresiones como DDRB y PORTB dejan de ser nombres aislados y pasan a representar la relación concreta entre las instrucciones de la CPU y la electrónica que existe detrás de cada pin.

El ejemplo del LED es elemental, pero el principio es el mismo cuando el pin controla una señal de habilitación, una entrada de otro circuito digital, una línea de comunicación o cualquier otra interfaz eléctrica. Cambia la aplicación; la relación fundamental entre software, registros, lógica interna del puerto y señal eléctrica permanece.
