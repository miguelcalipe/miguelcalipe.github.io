SISTEMAS EMBEBIDOS: FUNDAMENTOS, ARQUITECTURA Y APLICACIONES

1. INTRODUCCIÓN

Un sistema embebido (embedded system) es un sistema informático especializado diseñado para cumplir una función determinada dentro de un equipo, máquina o producto. Su hardware se construye alrededor de un dispositivo de procesamiento, que puede ser un microprocesador o un microcontrolador (MCU, Microcontroller Unit).

A diferencia de un computador de propósito general, un sistema embebido no está pensado para ejecutar una amplia variedad de aplicaciones para un usuario. Su diseño está orientado a resolver una tarea concreta o un conjunto limitado de tareas. Puede, por ejemplo, medir una variable física, procesar esa información, tomar una decisión y controlar un actuador.

Esto no significa que todos los sistemas embebidos tengan la misma arquitectura. El hardware utilizado depende directamente de los requisitos del sistema: capacidad de procesamiento, memoria, entradas y salidas, consumo energético, costo, tamaño, tiempo de respuesta y condiciones de funcionamiento.

En términos generales, un sistema embebido combina hardware, software y periféricos especializados para realizar una función específica de manera autónoma y confiable.

2. CARACTERÍSTICAS FUNDAMENTALES DE UN SISTEMA EMBEBIDO

Aunque existe una gran variedad de sistemas embebidos, hay varias características que permiten reconocerlos.

2.1. Función Especializada

Un sistema embebido normalmente está diseñado para realizar una tarea bien definida.

La tarea puede ejecutarse:

  • periódicamente;
  • como respuesta a un evento;
  • como consecuencia de una señal proveniente de un sensor;
  • o mediante una combinación de estas situaciones.

Por ejemplo, un controlador puede leer periódicamente un sensor de temperatura y modificar una salida para mantener una temperatura determinada.

El sistema no necesita disponer de todas las capacidades de un computador personal. Solo necesita los recursos necesarios para realizar correctamente la función para la cual fue diseñado.

2.2. procesamiento y computación

Los sistemas embebidos tienen capacidades de procesamiento y cálculo que dependen de la aplicación.

En algunos casos basta con un microcontrolador sencillo. En otros se necesita un dispositivo con mayor capacidad de procesamiento.

La elección del procesador está relacionada directamente con los requisitos del sistema. Una computadora para bicicleta, por ejemplo, puede realizar sus cálculos con un microcontrolador de recursos relativamente modestos. En cambio, una unidad de control de un motor de automóvil necesita procesar una cantidad mucho mayor de información y cumplir restricciones temporales más exigentes.

2.3. Bajo Consumo Energético

Muchos sistemas embebidos funcionan con una fuente de energía limitada, como una batería. Por esta razón, el consumo energético es un parámetro importante durante el diseño.

El consumo no puede analizarse de forma independiente de los demás requisitos. Aumentar el rendimiento del procesador puede incrementar el consumo, mientras que reducir demasiado la capacidad de procesamiento puede impedir que el sistema cumpla sus tiempos de respuesta.

Por ello, el diseño busca un equilibrio entre:

  • rendimiento;
  • consumo de energía;
  • costo;
  • tamaño;
  • capacidad de procesamiento.

2.4. Bajo costo y tamaño reducido

Los sistemas embebidos suelen estar integrados dentro de productos que tienen restricciones de costo y espacio.

Una computadora para bicicleta, por ejemplo, debe ser pequeña, ligera, económica y capaz de funcionar durante un período prolongado con una batería.

En aplicaciones automotrices también existe una restricción importante de espacio. La unidad electrónica debe integrarse en un vehículo donde el tamaño del dispositivo y sus condiciones de instalación son factores relevantes.

2.5. Funcionamiento Autónomo

Muchos sistemas embebidos deben funcionar durante largos períodos sin intervención directa de un operador.

Esto introduce un requisito importante: el sistema debe ser capaz de manejar condiciones de fallo sin bloquearse o detener completamente su funcionamiento.

El software de un sistema embebido, por tanto, no solo debe contemplar el funcionamiento normal. También debe incluir mecanismos para detectar, gestionar y diagnosticar determinadas condiciones anómalas.

3. PROCESAMIENTO EN TIEMPO REAL

Una característica especialmente importante de muchos sistemas embebidos es su relación con el tiempo real (real-time).

Un sistema en tiempo real debe producir una salida significativa dentro de un intervalo de tiempo definido. No basta con obtener el resultado correcto; también es necesario obtenerlo dentro del plazo establecido.

Esto es fundamental en aplicaciones donde el momento en que se produce una respuesta forma parte del comportamiento correcto del sistema.

Por ejemplo, en una unidad de control del motor de un automóvil, los cálculos relacionados con la inyección de combustible y el encendido deben realizarse en momentos determinados. Si el cálculo termina demasiado tarde, aunque el valor calculado sea correcto, el sistema puede funcionar de manera incorrecta.

Por eso, en un sistema de tiempo real existen dos aspectos que deben considerarse:

  • Corrección del resultado.
  • Cumplimiento del tiempo de respuesta requerido.

Por ejemplo, la computadora para bicicleta es un sistema de tiempo real débil (weak real-time system). En este caso, el procesamiento debe realizarse entre dos impulsos del sensor de la rueda, pero los requisitos temporales no son comparables con los de sistemas de control más críticos.
